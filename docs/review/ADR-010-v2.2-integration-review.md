## 4. Questions for the maintainer

These were left as written, because each needs a decision.

1. **Is the journal signed?** PUB-007 says "signed journal", but nothing
   defines journal signing. Plan §6.1 calls the journal minimal,
   non-sensitive metadata, and the seal manifest carries the digests. You
   could drop "signed", so that the seal-manifest digest is the check. Or you
   could specify an HMAC keyed from the signed-in user's DEK.
2. **Which bootstrap channel?** (ADR §6, item 2.) Java has no portable way to
   use an inherited Windows handle by number. The child's stdin pipe is the
   most portable private, one-time channel. D-03 allows stdio for bootstrap
   only with an approved threat model. Recommendation: test it in G0, then
   approve or reject it with the evidence.
3. **Are synced folders supported?** On Windows and Linux, the default data
   root is under `~/Documents`, which a sync client may manage. Should G3
   support that location, or should Help list supported locations?
   `PUBLISH_UNSUPPORTED` in Appendix B points users to Help.
4. **Replace v2.1?** This branch puts v2.2 at the canonical paths and keeps
   v2.1 in `docs/design/adr-010/v2.1/`. Neither is accepted. Confirm this
   arrangement or say how v2.1 should be retired (review §8).
