## Review disposition

The DataFusion objective is retained, but an **all-DataFusion implementation is not predetermined**. The old draft remains under `reference/v0.1/`. The canonical v0.2 documents are in `docs/design/`, `docs/testing/`, and `docs/agent/` in this ZIP. The feasibility spike is independently authorization-gated. ## Additional conflicts resolved

- Historical DuckDB `PortfolioRollup` may be expressible more simply and faster in checked Go; this does not demote DataFusion's role for complex file analytics and future S7A.
- A 10,000-row response is a **bounded preview**, not a complete import. The old UI remains backward-compatible until a versioned API is approved, but truthful truncation flags are mandatory in the replacement.
- DataFusion query memory and process RSS are **different limits**. Spill data may be decrypted project information. No-spill must be *enforced and demonstrated*, not presumed.
- Host-only source path authority is preserved while a performant seek-based protocol is evaluated. Do not pretend an ordinary sequential gRPC stream has native Parquet row-group pruning without an adapter.
- Both `LC-GATE` and `DF-G*` are mandatory: a legal disclosure cannot establish feature parity, and parity cannot resolve distribution licensing.
- Release compatibility covers Windows/minimum macOS/Linux as actually advertised on execution date; unavailable signing devices or systems are BLOCKED.

## Owner decisions (recommendations; NOT accepted by this review)

1. Accept the revised target and the requirement to compare three architectures; **do not select method ownership yet**.
2. Authorize only DF0 isolated prototypes and reference benchmark work after doc acceptance; no `go.mod`/production/installer change.
3. Accept `SENSITIVE_MEMORY_ONLY` for decrypted project projections, without authorizing protected spilling.
4. Treat the PR #146 TPC-H/TPC-DS release blocker as an independent binding constraint; preserve notices for other components.
5. Require representative hardware budgets and format oracles before accepting end-to-end regressions.
6. Retain all 65 tests; any unverifiable gate is BLOCKED, never silently dropped.
7. After DF0, hold a separate decision selecting DuckDB-free method allocation and authorizing DF1 or rejecting replacement if it cannot meet required parity/security.
