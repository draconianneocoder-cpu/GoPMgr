# Coding agent — maintainer acceptance of ADR-010 v2.2

The maintainer has **accepted the architectural direction** of ADR-010 v2.2, D-01–D-19 and QI-01–QI-15, and expressly accepted the decisions **OWN-01 through OWN-11** and four integration questions **INT-01 through INT-04**, as recorded in `ADR-010-v2.2-ACCEPTED-OWNER-DECISIONS.md`. Read that entire document; it controls any ambiguous shorthand below.

**Effective status:** ACCEPTED architecture, **not implemented**. Preserve all binding guarantees. Do not infer transport viability, license compliance, test PASS, supported filesystem guarantees, or production deployment from this acceptance.

**What is authorized now:**

1. **P00 docs-only:** Incorporate this accepted decision record into the canonical v2.2 ADR, plan owner register, test strategy, integration review, crosswalk and agent controls. Preserve archival v1/v2.0/addendum/v2.1 unchanged. Record owner acceptance and date; do not alter prior history.
2. **P01/G0 isolated feasibility:** Real cross-platform Go↔Java gRPC/HTTP2 over UDS, Windows named pipes and alternate Windows AF_UNIX; endpoint/bootstrap security, bidirectional streaming, backpressure, cancellation, package/signing feasibility, dependency/license study. Prototype code only; no production feature path.
3. **P02/S0 evidence-only:** Current source/schema/format/storage census, performance baselines, representative hardware and fixtures, supported local-storage/rename/WAL behavior and preliminary budgets. No schema migration or existing-file relocation.

**Hard constraints:** No custom stdio-based project RPC and no unapproved TCP fallback; no weakening of internal plugin registry, source fidelity, encryption, audit, user approval, 50k-task editability, AI restrictions or cross-platform honesty. Stdio is a one-shot bootstrap candidate only. Windows named-pipe gRPC remains UNPROVEN until tested with a real Java client. Retained encrypted evidence must publish with the project. Authenticate recovery journals with an approved reviewed HMAC/key lifecycle; HMAC is not an anti-rollback guarantee. Do not treat legacy projects without import journals as orphans. Do not use cloud-sync detection heuristics to delete, move or unconditionally reject existing project data. Do not assert LGPL or signing compliance until legal/package review.

**No authorization yet:** G1+ production code/dependencies, ADR-011 implementation/migrations, worker release, project publication, G5+ AI/third-party features, changed storage root, or published installer. Request a separately accepted next work slice after G0/S0 evidence. On conflict, submit an ACR rather than changing quality criteria or tests.

**Report before editing:** current branch/HEAD/status; exact approved phase; relevant QI/D/OWN/INT/test IDs; proposed scoped files; negative cases and evidence plan; any blockers or ACRs. Report afterward: exact diffs, executed commands/results, failures and omissions, privacy/security and schema implications, and remaining owner decisions. Do not claim repository application until it is actually committed.
