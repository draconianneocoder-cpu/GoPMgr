# ADR-003: PDF library migration

**Status:** Implemented
**Decision date:** 2026-06-25

## Context

GoPMgr generates project documents, charts, PDF/A output, and PAdES-signed
exports. The prior `jung-kurt/gofpdf` dependency was archived and no longer a
suitable maintenance path.

## Decision

Use `github.com/go-pdf/fpdf`, the maintained continuation of gofpdf, for PDF
generation. Keep PDF/A metadata and PAdES mutation in GoPMgr-owned code rather
than coupling those compliance steps to a renderer implementation.

## Consequences

- Renderer behavior needs regression coverage for layout and generated bytes.
- PDF/A output must be validated independently of a successful render.
- PAdES remains the final PDF mutation; later changes require re-signing.
- Dependency updates require the usual maintenance, license, build, and
  release-gate review.

## Verification

Document and chart renderer tests cover application behavior. `make check-pdfa`
and the PAdES gates provide release evidence for PDF output.
