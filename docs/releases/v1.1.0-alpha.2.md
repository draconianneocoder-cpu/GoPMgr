- **Publication:** published as a GitHub prerelease on 2026-09-08 at
  <https://github.com/draconianneocoder-cpu/GoPMgr/releases/tag/v1.1.0-alpha.2>.
- **Classification:** public GitHub prerelease for limited engineering
  validation; not a beta, stable release, or supported-platform claim.
- **Release operator:** GitHub account `draconianneocoder-cpu`.

## Entry evidence

The following commands passed on macOS 26.6.2 arm64 from a clean checkout at
the pre-record source baseline:

```text
make verify
make lint-all
make license-check
make coverage-ledger-drift
make release-scope
make check-release
GOPMGR_RELEASE_TAG=v1.1.0-alpha.2 make tag-preflight
```

This includes owned Go-package tests and race checks, 394 frontend tests,
Svelte diagnostics, the production Wails build, REUSE coverage (741 of 741
files), the 43-package coverage ledger, encrypted-database validation, strict
PDF/A validation, and deterministic/external PAdES harnesses. After this record
was committed, exact candidate `ad5c134a13335f5bfa69e147d7bc7390f5d0a76b`
passed the local tag preflight and all eight jobs in GitHub Actions branch run
`34085530082`, including blocking `govulncheck`. Tagged release run
`34281553558` then passed its full preflight, all three native package jobs,
and draft creation. The scan found no reachable vulnerabilities; that is not a
claim that the dependency graph contains no advisories.

## P0 and P1 dispositions

These open items do not satisfy the wider-beta exit criterion. They are
accepted only as disclosed limitations of this narrowly classified alpha:

| Open item | Alpha disposition |
| --- | --- |
| Prevent silent editor data loss | Protection is implemented and unit/race-tested. Native window close was exercised for all four dirty-registering editors on a local unsigned macOS arm64 build; Cmd+Q was exercised only for `SprintList` and `ProjectSettings` as representative paths. Linux and Windows native-close behavior is not verified. Keep the item open and do not claim complete cross-editor or cross-platform native verification. |
| Validate package lifecycles | Keep open. macOS has prior local selected lifecycle evidence, Linux has structural inspection only, and Windows is untested. Every attached package remains an evaluation artifact. |
| Sign and notarize distributables | Accepted alpha limitation. All packages are unsigned; the macOS DMG is not notarized. A matching published SHA-256 digest detects a transfer mismatch, but does not establish publisher identity or replace Developer ID signing, notarization, Authenticode, or platform trust checks. |
| Configure the signed update channel | Accepted alpha limitation. Repository variable `GOPMGR_UPDATE_PUBLIC_KEY` and repository secret `GOPMGR_UPDATE_PRIVATE_KEY` are absent, so this build's update channel is disabled. |
| Obtain trusted PAdES evidence | Accepted alpha limitation. Deterministic and external-validator checks use a self-signed fixture and do not establish a publicly trusted certificate chain. |
| Complete keyboard and assistive-technology smoke coverage | Accepted alpha limitation. First run, project editing, reports, native window controls, VoiceOver, NVDA, and Narrator are not comprehensively exercised. |
| Close the CI-only PAdES harness race | Keep open as trending resolved. The atomic-directory fix has consecutive clean hosted runs, including the candidate branch run, but the backlog's formal close criterion has not been declared met. |
| Complete the shared component-library migration | Deferred, non-blocking maintainability work. Raw controls remain in many screens; no completion claim is made. |

Cost Control Phase 1 remains project-local, fixed to two-decimal amount
semantics, and separate from the legacy Budget rollup. It has no FX conversion,
reserve drawdown, time-phased cash-flow, automatic EVM integration, or
financial RBAC. Existing JPY projects are readable but Cost Control is
read-only; this release does not claim exponent-aware JPY support.

## Backup and migration recovery action

Before installing or opening this alpha against existing data:

1. Quit GoPMgr and confirm no GoPMgr process remains.
2. In the currently installed build, record the application data location
   shown in Application Settings. Back up the complete `GoPMgr` data directory
   to a timestamped sibling or offline location. Preserve `system.db`, every
   per-user project directory and `.gopmgr` file, certificates, exports, and
   recovery material together; do not copy a live database piecemeal.
3. Preserve the one-time account recovery codes separately from the device.
4. For important projects, also create and integrity-check a `.pmba` project
   archive before migration. The archive is a project snapshot, not an account
   backup: it does not replace `system.db`, the compatible account and wrapped
   data-encryption key, or separately stored recovery codes.

If this alpha performs plaintext-to-SQLCipher migration, keep the private
`<project>.pre-encryption.bak` until the encrypted project opens successfully
and a new `.pmba` archive has been verified. That file is plaintext and must be
protected accordingly.

Recovery is forward-only for this alpha: quit GoPMgr, move the affected active
data directory aside without deleting it, reinstall the same or a newer
GoPMgr build, and restore the complete pre-alpha data-directory backup. A
verified `.pmba` can restore a project only after the compatible account and
wrapped data-encryption key in `system.db` are available; it cannot recover the
account or key material by itself. The `.pre-encryption.bak` is
schema-migrated and does not demonstrate compatibility with
`v1.1.0-alpha.1`. Downgrading an upgraded data directory to alpha.1 is
unsupported and must not be used as a recovery procedure.

## Publication and withdrawal controls

Publish only when the final tag workflow is green and the draft assets,
digests, prerelease flag, title, and limitation-first notes have been reviewed.
After publication, run install, launch, persistence, and removal checks against
the downloaded artifacts on each platform before changing any artifact from
"evaluation" or "unverified" status.

Withdraw the release from recommendation without moving its tag if a required
gate fails or evaluation finds data loss, cross-project disclosure, migration
failure, update-integrity failure, export-integrity failure, an artifact or
digest mismatch, or materially overstated release notes. Repair on a new
commit and issue a new alpha sequence.
