# ADR-012 DF0 spike

This is the isolated feasibility spike authorized by the maintainer on
2026-10-26
([acceptance record](../../docs/review/ADR-012-v0.2-ACCEPTED-OWNER-DECISIONS.md)).
It is evidence only:

- It is not part of the GoPMgr build.
- It changes no production code, `go.mod`, build tag or package.

Results are recorded in
[`docs/testing/adr-012-df0-evidence.md`](../../docs/testing/adr-012-df0-evidence.md).

## Isolation

- The spike is its own Go module, `gopmgr/spikes/adr012-datafusion`, so the
  main module ignores this directory.
- It uses `replace gopmgr => ../..`, which lets it import the shipped
  `gopmgr/internal/analytics` engine unchanged.
- The packages the engine compiles from are the same modules at the same
  versions as the app: duckdb-go v2.10506.0 and bindings v0.10506.0.
  `environment.json` records this on every run.

## Layout

| Path | What |
|---|---|
| `internal/fixtures` | Seeded synthetic corpus: 24 portfolio and 70 tabular cases (CSV, TSV, TXT, JSON, NDJSON, Parquet), each carrying the logical truth the generator wrote. No TPC data |
| `internal/oracle` | Independent big-integer portfolio oracle. It keeps the legacy-parity verdict separate from the financial-correctness verdict (DF-A05) |
| `internal/canon` | Engine-neutral cell comparator and parity classes |
| `cmd/df0-fixtures` | Writes the corpus. `-check` compares it with `fixtures/manifest.json` (SHA-256 of every file and of its expected rows) |
| `tools/independent_read.py` | Reads Parquet with pyarrow and JSON with Python's `json` module, for the fixture self-check |
| `cmd/df0-selfcheck` | Proves every fixture against an independent reader before any engine is judged |
| `cmd/df0-baseline` | Runs the shipped DuckDB engine (A) over the corpus |
| `rust/` | Candidate B: a DataFusion 55.2.0 engine (`engine`) and its one-shot CLI (`cli`). Crate versions are locked in `Cargo.lock`; the toolchain in `rust-toolchain.toml` |
| `internal/gorollup` | Candidate C: the portfolio rollup in Go with checked 64-bit sums |
| `cmd/df0-candidates` | Runs candidates B and C over the corpus, next to engine A's verdicts |
| `proto/df0ipc.proto` | DF0-C spike contract (not the production G1 contract). Go code in `internal/df0pb` and Rust code in `rust/worker/src/pb` are generated by `scripts/generate-df0ipc.sh` with pinned tools and committed |
| `internal/ipchost` | DF0-C host: one private Unix socket per job, peer-PID admission of only the launched worker, a single-use expiring launch proof, the stream driver, Linux `/proc` inspection and per-child post-reap resource accounting |
| `internal/source` | DF0-C2 host-owned bounded immutable snapshots and expiring per-job range grants |
| `rust/engine/src/host_source.rs` | DF0-C2 job-local read-only Parquet object store; no host path or file/remote provider |
| `internal/rollupwire` | Host-side money normalization and result conversion for B's rollup, shared by the CLI and gRPC runs |
| `rust/worker` | DF0-C worker: a gRPC client over the Unix socket only. It checks that the socket is served by its parent before sending anything |
| `cmd/df0-ipc` | Runs every DF0-C scenario against the real worker |
| `evidence/` | JSON and JSONL evidence, synthetic only. It contains no user paths or data |

## Reproduce DF0-A

```sh
python3 -m venv /tmp/df0-venv && /tmp/df0-venv/bin/pip install pyarrow==22.0.0
PYTHON=/tmp/df0-venv/bin/python spikes/adr012-datafusion/scripts/run-df0a.sh
```

The run needs Go 1.27.3 with CGO, as for GoPMgr, and network access the
first time, to download modules.

## Reproduce DF0-B

```sh
spikes/adr012-datafusion/scripts/run-df0b.sh
```

This needs the installed Rust 1.99.1 toolchain managed by `rustup`.
Install it explicitly if absent (`rustup toolchain install 1.99.1 --profile minimal`).
The reproduction and code-generation scripts use `scripts/with-rust-toolchain.sh`
to select its Cargo, compiler and rustdoc even when Homebrew shadows rustup
proxies. Dispatch through `rustup run` preserves rustup's runtime library setup
as well. Missing selected tools fail without automatic installation or fallback.
The launcher changes only its child environment; it does not change rustup's
global default. Existing compiler wrappers are not neutralized.

Cargo builds into `CARGO_TARGET_DIR`, which defaults to a directory outside the
repository. Do not build into `rust/target`: `reuse lint` scans that
directory even though git ignores it.

## Reproduce DF0-C (Linux)

```sh
spikes/adr012-datafusion/scripts/run-df0c.sh
```

Every scenario launches a fresh worker on a fresh endpoint. The host supplies
an empty launch environment; native runtimes may add variables, whose names
Hello reports. The credential travels on stdin, never in argv.

## Reproduce DF0-C2 (native macOS or Linux)

```sh
DF0_READAT_EVIDENCE=/absolute/path/to/readat.json \
  bash spikes/adr012-datafusion/scripts/run-df0c2.sh
```

This builds the pinned worker and runs 18 C2 and 3 existing-operation native
scenarios. The evidence path is optional; without it the tests report their outcomes without writing records.
The source is captured once in bounded host memory before each job. Both range
and sequential modes pay the full capture cost. Range traffic, full host source
reads and end-to-end time are reported separately. These single-run observations
are not the DF0-E performance qualification. See the
[DF0-C2 record](../../docs/testing/adr-012-df0-c2.md) for guarantees and limits.

## Reproduce the DF0-D2 no-spill experiment (native macOS)

```sh
DF0_NO_SPILL_EVIDENCE=/absolute/path/to/no-spill.json \
  bash spikes/adr012-datafusion/scripts/run-df0d2-no-spill.sh
```

This runs eight synthetic spill/denial/lifecycle scenarios, the OS denial
self-test and the 21 existing native regressions. See the
[scope and proof limits](../../docs/testing/adr-012-df0-no-spill.md).
It does not complete host-wide admission, OS-wide observation or production
containment qualification. Linux refuses the experimental denial mode.

The [native observer and App Sandbox experiment](../../docs/testing/adr-012-df0-observer-sandbox.md)
measures current usage, missed bursts and controlled termination, and runs signed
Rust copies over native UDS with OS access restrictions. Own-container writes
remain allowed. This is isolated feasibility, not hard quotas, memory-only
confidentiality or production adoption. See its exact reproduction and limits.

The later [nested frame repair](../../docs/testing/adr-012-df0-nested-frames.md)
qualifies selected child spans and null-aware view compaction in five common
containers. Its Rust regressions exercise actual views; five real-worker jobs
separately check ordinary nested-string compatibility, refusal and recovery.
This does not complete nested-schema, containment or production qualification.

## Resource accounting (macOS first)

The host records per-child peak RSS and user/system CPU time after reaping each
worker, including failures and forced termination. It uses kernel wait accounting
rather than the worker's Linux-only self-report. These are lifetime child
measurements, not simultaneous host-wide memory, CPU quotas or process-tree sums.
See the [resource accounting record](../../docs/testing/adr-012-df0-resources.md)
for native 2/4/8-worker checks, reproduction and remaining admission work.

## Pre-launch reservations (macOS first)

`internal/ipchost.Admission` coordinates declared job, memory and CPU-slot
reservations before launch and holds them until cleanup completes. Native
2/4/8-worker cohorts reject excess claims and then recover capacity. See the
[admission record](../../docs/testing/adr-012-df0-admission.md) for reproduction,
fault controls and limitations. Reservations do not enforce actual RSS, CPU
rate or descendant processes; raw baseline `Run` remains outside this controller.

## Toolchain evidence

The maintainer approved four temporary, spike-only dependency overrides on
2026-10-31 to remove the vulnerable Zstd branch. See
[provenance, licensing and removal](third_party/GOPMGR.md) and the
[assessment](../../docs/testing/adr-012-df0-zstd-assessment.md). The source
guards run in the root `make config-check`; workspace tests include interrupted
Zstd context reuse. The production Go graph and DuckDB are unchanged.

The current pin is Rust 1.99.1; the declared MSRV remains 1.94. Historical
DF0-B/C records retain their original compiler observations. A collector's
`rustc --version` field describes the compiler visible to that process, not
proof of an earlier binary's build. Associate fresh build logs, source and lock
hashes, compiler identity and artifact hashes for current qualification.
See [Rust 1.99.1 verification](../../docs/testing/adr-012-rust-1.99.1.md).

## Native macOS limit primitives

From this spike directory:

```sh
go test -race -count=1 -v ./internal/ipchost \
  -run 'TestMacOS(LimitPrimitives|ProcessGroupMemberCanEscape)$'
```

These bounded synthetic subprocess probes require no DataFusion worker. They
qualify the distinctions between address-space and resident memory, per-process
CPU time and aggregate quotas, and process groups and containment. They do not
establish production enforcement. See the [measurements and limits](../../docs/testing/adr-012-df0-macos-limits.md).

The later pre-exec probes distinguish installed limits from actual effects:

```sh
DF0_WORKER=/absolute/path/to/reviewed/df0-worker \
DF0_EXEC_LIMIT_EVIDENCE=/absolute/path/to/existing-directory \
  go test -race -count=1 -v ./internal/ipchost \
  -run '^TestMacOS(AbsoluteExecLimits|ChildCreationLimit|NativeWorkerExecLimits)$'
```

The synthetic tests compile a standalone C probe with existing `xcrun clang`.
The native-worker test skips without `DF0_WORKER`; NPROC checks skip as root.
Direct fork/spawn refusal survived exec and a Rust generation job completed,
but practical AS ceilings were refused. A successful larger AS control denied
a mapping without establishing an RSS cap. See the
[follow-up evidence and proof limits](../../docs/testing/adr-012-df0-macos-limits.md#absolute-limits-across-exec-and-child-creation-follow-up).

### Artifact-bound SPDX build-input export

The default inventory output remains unchanged. The optional `-format spdx3`
uses a successful Cargo JSON worker build log and hash-bound native observations.
From the repository root, capture a build with the same reviewed target cache:

```sh
CARGO_TARGET_DIR=/absolute/path/to/reviewed-target-cache \
  bash spikes/adr012-datafusion/scripts/with-rust-toolchain.sh cargo build \
  --manifest-path spikes/adr012-datafusion/rust/Cargo.toml --locked --offline \
  --release -p df0-worker --message-format=json > /absolute/path/to/build.jsonl
```

From this directory, using the locked metadata generated above:

```sh
go run ./cmd/df0-inventory -repo-root ../.. -target aarch64-apple-darwin \
  -format spdx3 -build-log /absolute/path/to/build.jsonl \
  -worker /absolute/path/to/reviewed-target-cache/release/df0-worker \
  -native-evidence evidence/df0-f-macos/native-worker.json \
  -created YOUR_RFC3339_OBSERVATION_TIME -revision YOUR_FULL_SOURCE_SNAPSHOT_SHA \
  < /absolute/path/to/metadata.json > /absolute/path/to/worker.spdx.json
```

A new worker hash requires new native observations; an old native evidence file
is rejected. `created` and `revision` are explicit operator observations, not
inferred build provenance. Stable inputs produce stable output. The recorded
worker was cached, not cleanly rebuilt; the source snapshot and build inputs
do not establish reproducibility or exact final linker contents.

Validate in a task-only Python environment with `jsonschema==4.26.0`,
`pyshacl==0.40.2` and `rdflib==7.6.0`. The complete captured environment is in
[evidence provenance](evidence/df0-sbom-macos/provenance.json). Obtain these
versioned official resources and retain them locally:

- [JSON schema](https://spdx.org/schema/3.0.1/spdx-json-schema.json)
- [JSON-LD context](https://spdx.org/rdf/3.0.1/spdx-context.jsonld)
- [SHACL model](https://spdx.org/rdf/3.0.1/spdx-model.ttl)

```sh
/absolute/path/to/task-venv/bin/python tools/validate_spdx3.py \
  /absolute/path/to/worker.spdx.json --schema /absolute/path/to/schema.json \
  --context /absolute/path/to/context.json --model /absolute/path/to/model.ttl \
  --negative-controls
```

The validator refuses resource hashes other than its pinned official bytes,
checks identity uniqueness and runs schema plus SHACL without external context
fetches or added RDFS inference. It is scoped to this generated document.
Declared SPDX expression syntax/identifiers were checked separately using the
existing `license-expression 30.4.4` validator; that is not a legal conclusion.
The [build SBOM and bounded source/notice review](../../docs/interoperability/adr-012-rust-dependency-security-sbom.md#artifact-bound-spdx-build-input-sbom)
remain partial F/F2 evidence, with no production integration or LC-GATE pass.

### Native-source and notice review inputs

`tools/native_review.py` uses Python 3.11+ standard-library modules and the
existing `ar` tool. From the repository root, use the same locked metadata,
completed Cargo JSON build log and reviewed worker as the SBOM export above:

```sh
python3 spikes/adr012-datafusion/tools/native_review.py \
  --metadata /absolute/path/to/metadata.json \
  --lock spikes/adr012-datafusion/rust/Cargo.lock \
  --build-log /absolute/path/to/build.jsonl \
  --native-inputs spikes/adr012-datafusion/evidence/df0-sbom-macos/native-inputs.json \
  --worker /absolute/path/to/reviewed-target-cache/release/df0-worker \
  --worker-evidence spikes/adr012-datafusion/evidence/df0-f-macos/native-worker.json \
  --crate-cache /absolute/path/to/cargo/registry/cache \
  --output-dir /absolute/path/to/new-review-directory

PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s spikes/adr012-datafusion/tools -p native_review_test.py
```

Tests require the existing C compiler (`cc`) and `ar`. The generator runs no
build scripts and fetches nothing. Output must be a new directory; input
validation and assembly finish before it is published. Its `source-review.json`
is evidence metadata; `NATIVE-REVIEW-NOTICES.txt` contains third-party texts and
must keep `LicenseRef-Third-Party-Notices` treatment rather than CC0. The recorded
copies live under `evidence/df0-native-source-macos/` and `notices/` respectively.
Compare both generated files byte for byte with those copies before updating
review evidence; do not replace old output in place.

File hashes cover entire published native-wrapper packages. Object/source
matches are unique candidates, not proof of compiler flags, include closure or
retained executable bytes. Raw C/header/assembly/include SPDX markers are
recorded without legal conclusions; unscanned files and absent markers remain
distinct. See the [native source review](../../docs/interoperability/adr-012-rust-dependency-security-sbom.md#native-source-provenance-and-notice-review-bundle)
for counts, licensing distinctions, refusal controls and remaining gates.
